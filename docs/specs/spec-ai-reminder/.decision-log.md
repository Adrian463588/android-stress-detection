# Decision Log: AI+ Reminder

## 2026-09-08 — Accepted contract

- The model may choose one reminder time, but the app enforces future/48-hour,
  one-per-session, and 24-hour delivered cooldown bounds.
- WorkManager is the scheduler because the feature tolerates approximate timing;
  exact alarms are intentionally out of scope.
- Background grounding is one valid persisted stress-session projection only.
  RAG, transcript, web, raw PPG, and full chat remain interactive AI+ concerns.
- Display name/message use the existing AndroidX Security Crypto/Keystore
  boundary. Room stores metadata and encrypted payload key only.
- Notification permission is an opt-in delivery capability and must not gate
  sensor monitoring or session capture.
- Invalid/unsafe model output is rejected, not rewritten into a static response.
- Physical device and model gates are separate from static code gates; absent
  hardware/model evidence is `BLOCKED`.
